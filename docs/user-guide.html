Vitals Monitor User Guide

Vitals Monitor is a free, ad-free Windows system-health dashboard that watches hardware, storage, and network telemetry in the background, automatically captures abnormal periods to a local SQLite database, and turns them into dense, exportable timelines for diagnosis.

Version 0.1.0 Windows x64 Local-first telemetry Updated August 2026
01 / INTRODUCTION

What Vitals Monitor does

Vitals Monitor stays active in the Windows system tray and samples the health signals exposed by your computer. During normal operation it uses a low-overhead polling interval and keeps only the latest five sample sets in working memory. When it detects a warning, a critical value, or a significant change, it moves to realtime polling and records the complete metric set to a local database.

This event-focused approach is intended to preserve the useful context around intermittent heat, load, cooling, storage, voltage, and network problems without requiring continuous high-frequency recording.

Copy-ready distribution description

The following description is the canonical introduction for release pages, application directories, package managers, and other distribution channels.

Full description
Vitals Monitor is a free, ad-free Windows system-health dashboard that watches hardware, storage, and network telemetry in the background, automatically captures abnormal periods to a local SQLite database, and turns them into dense, exportable timelines for diagnosis. It is supported by SorryNeedBoost Studios.
Short listing line
Free and ad-free, Vitals Monitor watches Windows hardware, storage, and network health and automatically logs abnormal periods for fast visual diagnosis.

Core capabilities

  • Monitor CPU, GPU, motherboard, memory, fan, voltage, disk, latency, jitter, and packet-loss values where the machine exposes them.
  • Detect threshold violations and meaningful movement across a rolling five-sample window.
  • Record all metrics at a one-second interval during automatic or manual logging.
  • Review database readings on a dense timeline with explicit start, stop, and marker events.
  • Export selected time periods to JSON and import compatible captures from other computers.

How Vitals Monitor is supported

Ad-free community project

Useful software, without interruptions

SorryNeedBoost Studios supports the application because useful, respectful software can demonstrate its values through the quality of the work while keeping commerce out of the user's task.

For a distributable desktop application, that support goes toward product design, engineering, testing, documentation, packaging, distribution, and ongoing maintenance rather than advertising inventory or promotional placement.

04 / INSTALLATION

Install, update, or remove the app

Install

  1. Download Vitals-Monitor-Setup-<version>-x64.exe from the official release location.
  2. Run the installer and approve the Windows administrator prompt.
  3. Review the destination folder. The default is C:\Program Files\Vitals Monitor.
  4. Choose whether to create a desktop shortcut and whether Vitals Monitor should start with Windows.
  5. Complete setup and launch Vitals Monitor.

The Start menu contains shortcuts for both the application and this user guide. When the startup option is selected, Vitals Monitor launches directly into the system tray without opening the dashboard.

Update

Exit Vitals Monitor from its tray menu, then run the newer installer. The stable application identifier allows Inno Setup to update the existing installation. User settings and the telemetry database live in the Windows profile and remain separate from installed program files.

Uninstall

Open Settings > Apps > Installed apps, locate Vitals Monitor, and choose Uninstall. Uninstalling program files does not automatically remove the telemetry database from your Windows profile.

05 / FIRST RUN

What to expect on first launch

  1. Vitals Monitor identifies the hostname, primary IP address, operating system, CPU, motherboard, GPU, and installed memory.
  2. The first telemetry sample is collected before the dashboard opens.
  3. The next four normal-interval samples populate the rolling five-sample history used for change detection.
  4. Available gauges appear in category rails around the timeline. Unsupported values appear as unavailable or are omitted.

The status bar shows the active mode, host identity, system summary, and direct controls for Help, Settings, and Tray.

Reading metric states

Normal
The value is available and below its configured warning threshold.
Warning
The value reached a warning threshold or changed significantly across the five-sample window.
Critical
The value reached its configured critical threshold.
Unavailable
The metric is not exposed by the current hardware or sensor interface. It does not trigger logging.

06 / MONITORING

How automatic monitoring works

01MonitorPoll every 10 seconds by default and keep the latest five sets in memory.
02DetectEvaluate thresholds and significant movement across the five-set window.
03RecordSwitch to one-second polling and write complete sets to SQLite.
04StabilizeStop automatic logging after five sets contain only normal or unavailable values.

Significant-change detection

Change detection begins when four previous values and the current value are available for the same metric. A change must meet both the configured percentage threshold and a unit-specific minimum movement. The defaults are 15 percent plus at least 4°C for temperature, 15 ms for latency, 300 RPM for fan speed, or one unit for other metric types.

A metric that passes this test is marked as a warning even when it remains below its ordinary warning threshold. That warning can start automatic logging.

Stabilization

Automatic logging does not stop as soon as one reading returns to normal. The entire rolling window must contain five sample sets in which every metric is normal or unavailable. Manual logging uses a different rule and continues until you stop it.

07 / DASHBOARD

Dashboard reference

Gauge rails

The left rail focuses on CPU, motherboard, voltage, and memory metrics. The right rail focuses on GPU, fan, disk, and network metrics. Select a category header to collapse or expand it.

Hover over a gauge to open a five-sample trend popover. Select the gauge to pin that popover; select it again or use the unpin control to dismiss it.

Timeline

The central chart uses database readings when logged data exists. Before any readings are recorded, it displays the current in-memory sample history. Colored vertical lines identify logging START, STOP, and user MARKER events.

Toolbar

  • Resolution reports the active polling mode and interval.
  • Manual Logging starts a manual realtime recording session. While a manual session is active, the command changes to Stop Logging.
  • Marker adds the text from the adjacent field to the event history.

Lower panels

  • Events lists start, stop, marker, warning, information, and import events.
  • Sensors lists current values, states, and warning or critical thresholds.
  • Archive selects a date and time range for JSON export or loads a prior Vitals Monitor JSON export.

The title bar status, status bar, toolbar, and tray icon all reflect the current recording state. The logging tray icon is visually distinct from the normal monitoring icon.

Manual sessions never auto-stop.

10 / MARKERS

Add event markers

Markers associate a timestamped note with the event timeline. Use them to record actions such as starting a benchmark, launching a game, changing a fan profile, reconnecting a cable, or reproducing a fault.

  1. Enter a concise note in the toolbar marker field.
  2. Select Marker.
  3. The note appears in the Events table and as a marker line on the timeline.

You can add markers while monitoring or logging. During an active session, the marker is associated with that recording session.

11 / EXPORT AND IMPORT

Move a capture between computers

Export a time range

  1. In the Archive panel, choose the From and To date and time.
  2. Select Export JSON.
  3. Choose a destination and filename in the Windows save dialog.

The export uses the schema identifier vitals-monitor.export.v1 and contains readings and events inside the selected range.

Import a capture

  1. Select Load JSON.
  2. Choose a JSON file previously created by Vitals Monitor.
  3. Imported readings and events are added to the local database and become available in the dashboard.
Exports can identify a computer.

Reading records include hostname, IP address, system-build information, timestamps, metrics, and logging reasons. Review exported JSON before sending it to another person or publishing it.

Import only trusted files. Unsupported schema identifiers are rejected, but an import appends records and is not intended as an undoable preview operation.

12 / SYSTEM TRAY

Tray and window behavior

  • Closing the custom window hides it to the tray. Monitoring continues.
  • Double-click the tray icon to restore and focus the dashboard.
  • Right-click the tray icon to show the app, start or stop manual realtime logging, open this guide, or quit.
  • Select Tray in the status bar to hide the dashboard without stopping the monitor.
  • Select Quit from the tray menu to stop monitoring and close the database cleanly.

If Vitals Monitor is configured to start with Windows, it uses hidden launch mode and remains in the tray until you open it. Starting the application again focuses the existing instance instead of creating a second monitor.

13 / SENSOR COVERAGE

Understand sensor availability

Vitals Monitor combines standard Windows and driver data with optional hardware-monitor WMI providers. Standard sources commonly provide CPU load, memory use, drive use, GPU information, and network test results. Temperature, voltage, and fan access varies more widely.

Extended motherboard, voltage, and fan values

On Windows, Vitals Monitor checks the WMI namespaces used by LibreHardwareMonitor and Open Hardware Monitor. If either provider exposes Temperature, Voltage, or Fan sensors, those values are added to the dashboard.

  1. Install and run a trusted release of LibreHardwareMonitor or Open Hardware Monitor.
  2. Enable its WMI sensor interface if the provider requires an explicit setting.
  3. Restart Vitals Monitor so the next collection cycle can discover the sensors.

Network values

Latency is the round-trip time to the configured target. Jitter is the standard deviation across up to five recent successful latency results. Packet loss is the percentage reported by the ping operation. A target that blocks ICMP may produce unavailable results even when ordinary web access works.

14 / DATA AND PRIVACY

Where data lives

Vitals Monitor processes telemetry locally. It does not upload system readings or send them to an application service.

Default database location
%APPDATA%\Vitals Monitor\data\vitals-monitor.sqlite3

The SQLite database stores settings, metric readings, event history, session identifiers, hostname, IP address, and system-build context. Current releases do not automatically prune old logged readings.

The only routine external network activity created by monitoring is the ICMP echo request sent to the configured latency target. The default target is Cloudflare's 1.1.1.1.

Back up or reset local data

Quit Vitals Monitor before copying, moving, or deleting the database. Copy the SQLite file to back up all local readings and settings. Deleting it resets local history and settings the next time the application starts; this action cannot be undone unless you have a backup.

15 / TROUBLESHOOTING

Common problems

The main window disappeared after I closed it

This is expected. Closing the window hides Vitals Monitor to the system tray so monitoring can continue. Double-click its tray icon to restore the dashboard. Use Quit in the tray menu when you want to stop the application.

Temperatures, fan speeds, or voltages show N/A

The hardware or driver may not expose that sensor through Windows. Run LibreHardwareMonitor or Open Hardware Monitor with WMI sensor access enabled, then restart Vitals Monitor. Some systems still restrict specific embedded-controller values.

Latency is unavailable or always critical

Confirm that the configured target responds to ICMP echo requests from your network. Corporate firewalls, VPNs, and some routers block ping. Choose a stable target appropriate for your network in Settings and test again.

Logging starts immediately after launch

At least one first-run metric has crossed a warning threshold. Check the Sensors table and Event history for the triggering label. High drive use, CPU load, temperature, or unusual network measurements are common causes. Adjust a threshold only after confirming the value is expected and safe for that system.

Automatic logging does not stop

Every available metric must remain clear across the full five-sample window. Review the Sensors table for warning or critical values. If the mode is manual, automatic stabilization does not apply; choose Stop Logging yourself.

A JSON file will not import

Only files with the vitals-monitor.export.v1 schema are accepted. Confirm the file was created by Vitals Monitor and was not edited, truncated, or converted by another tool.

The user guide will not open from the app

Confirm the installed file exists at resources\docs\user-guide.html under the Vitals Monitor installation directory and that Windows has a default application associated with HTML files. Reinstalling restores the packaged guide.

16 / FAQ

Frequently asked questions

Does Vitals Monitor need to stay open on the desktop?

No. It is designed to remain in the system tray. Hiding the dashboard does not interrupt polling or logging.

Does the application record continuously?

No. Normal monitoring retains five sets in memory. Database recording begins automatically for abnormal activity or manually when requested.

Can I force continuous one-second recording?

Yes. Start manual logging and leave it active. Manual mode continues until explicitly stopped and can grow the local database quickly over long periods.

Can I analyze a capture from another computer?

Yes. Export the required period to JSON on the source computer, transfer the file securely, and load it from the Archive panel on the analysis computer.

Does Vitals Monitor send telemetry to a cloud service?

No. Collected telemetry remains in the local SQLite database. Network quality monitoring pings only the latency target configured in Settings.

Why do I see fewer sensors than another computer?

Sensor exposure differs by motherboard, firmware, GPU driver, embedded controller, and monitoring provider. This is expected and does not indicate an installation failure.
